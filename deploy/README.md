# Деплой из GitHub Actions

В репозитории настроены workflow «Тесты» на каждый push и «Развернуть» для ручного обновления рабочего сервера. Ручной workflow запускается на `main` и сначала повторно выполняет полную регрессию для выбранного GitHub SHA. GitHub сохраняет результаты тестов и журнал установки.

## Запуск обновления

1. Отправьте изменения в `main` и проверьте результат workflow «Тесты».
2. Откройте [Actions → Развернуть](https://github.com/AlexanderSanes/SIGame2.0/actions/workflows/deploy.yml).
3. Нажмите **Run workflow**, выберите `main` и подтвердите запуск.
4. Дождитесь успешного завершения тестов и задания «Обновить сервер». В сводке будет SHA установленного коммита и ссылка на игру.

Workflow фиксирует коммит в момент запуска. Последующие push требуют нового запуска деплоя. Установка сериализована через GitHub concurrency и серверный `flock`. Идущая установка продолжает выполняться при запуске следующей.

Планируйте установку между играми. Перезапуск временно разрывает соединения, сервер сохраняет комнаты через SIGTERM, клиенты переподключаются со своими токенами. Список восстановленных комнат проверяется после запуска. Удаление пустых просроченных комнат продолжает работать по `ROOM_IDLE_MS`.

## Что установлено на сервере

- `/opt/sigame/releases/<SHA>` содержит код и production-зависимости конкретной версии.
- `/opt/sigame/current` указывает на текущую версию. Дополнение `/etc/systemd/system/sigame.service.d/deployment.conf` направляет службу на этот путь.
- `/var/lib/sigame` содержит рабочую SQLite, uploads и avatars. Данные общие для версий приложения.
- `/var/backups/sigame/<дата>-<SHA>-<суффикс>/data.tar.gz` содержит полную копию данных после штатной остановки службы. Рядом сохраняются путь предыдущей версии и список комнат.
- `/usr/local/sbin/sigame-deploy` выполняет установку, `/usr/local/sbin/sigame-deploy-ssh` проверяет SSH-команду.
- `/etc/sigame-deploy.conf` задаёт `NODE_BIN` и `PUBLIC_URL`. Файл доступен для записи только root.

При подготовке версии `npm ci --omit=dev` выполняется пользователем `sigame-deploy`, после установки владельцем файлов становится root. Ключ GitHub допускает только команду `deploy <40-символьный SHA>` и запрещает SSH-forwarding и терминал. Sudo разрешает этому пользователю только серверный скрипт деплоя. Ключ администратора хранится отдельно.

При ошибке после остановки службы скрипт возвращает прежнюю ссылку `current` и запускает предыдущий код. Резервная копия данных сохраняется для восстановления администратором. Изменения схемы БД в будущих версиях требуют проверки совместимости отката.

Каталоги версий и резервные копии накапливаются. Контролируйте место и удаляйте старые копии после проверки обновления, сохраняя текущую версию, предыдущую рабочую версию и нужные резервные копии. Архивы содержат токены комнат и доступны только root.

## Первичная настройка или перенос

На сервере должны работать `sigame` и nginx с HTTPS. Установите Node.js 22 с npm, Git, curl, tar, Python 3, sudo и утилиты Linux `flock` и `runuser`. Предполагаются код в `/opt/sigame`, данные в `/var/lib/sigame` и backend на `127.0.0.1:3000`. Для доступа к архивам исходников репозиторий должен быть публичным.

1. Создайте отдельную пару SSH-ключей Ed25519 для GitHub Actions. Закрытый ключ сохраните в секрете окружения GitHub, публичный скопируйте на сервер. Используйте отдельную пару для каждого сервера.
2. Скопируйте три скрипта из этого каталога на сервер. От root запустите установку, указав публичный ключ, фактический путь к Node.js и адрес сайта.

```sh
bash deploy/setup-actions.sh /root/github-actions.pub /opt/sigame-node/bin/node https://game.example.com
```

Установщик создаёт пользователя, ограниченный вход по ключу, конфигурацию sudo и дополнение systemd. Исходная установленная версия копируется в каталог `bootstrap-*` для первого отката. Служба использует новую схему при следующем запуске. Для повторной установки используйте публичный ключ действующей пары, команда заменяет выделенный `authorized_keys`.

3. В GitHub создайте environment `production` с разрешённой веткой `main`. Добавьте его секреты и переменные.

| Тип | Имя | Значение |
|---|---|---|
| Secret | `DEPLOY_SSH_KEY` | Полный закрытый ключ выделенной пары Ed25519 |
| Secret | `DEPLOY_KNOWN_HOSTS` | Строка known_hosts для адреса сервера с проверенным публичным ключом SSH-хоста |
| Variable | `DEPLOY_HOST` | Адрес сервера, например `95.217.174.64` |
| Variable | `DEPLOY_USER` | `sigame-deploy` |
| Variable | `DEPLOY_PUBLIC_URL` | HTTPS-адрес сайта без завершающего `/` |

Публичный ключ SSH-хоста получите через уже доверенное административное подключение или консоль сервера. Для текущего сервера используется ключ Ed25519 из `/etc/ssh/ssh_host_ed25519_key.pub`. Строка known_hosts имеет вид `<адрес> ssh-ed25519 <ключ>`.

4. Запустите «Развернуть» на `main` и проверьте журнал, `/healthz` и возврат в существующую комнату.

Серверные скрипты устанавливаются администратором. После изменения этих скриптов в Git повторно установите их через `setup-actions.sh` с действующим публичным ключом. Изменения workflow применяются после push.

## Диагностика и ручной возврат

Проверьте службу, её журнал и выбранную версию через административное SSH-подключение.

```sh
systemctl status sigame
journalctl -u sigame -n 100
readlink -f /opt/sigame/current
cat /opt/sigame/current/.release-sha
curl -fsS http://127.0.0.1:3000/healthz
```

Для возврата к сохранённой версии сначала убедитесь, что она совместима с текущей БД. От root подставьте нужный существующий каталог вместо `<SHA>`.

```sh
systemctl stop sigame
ln -s /opt/sigame/releases/<SHA> /opt/sigame/.current-rollback
mv -Tf /opt/sigame/.current-rollback /opt/sigame/current
systemctl start sigame
curl -fsS http://127.0.0.1:3000/healthz
```

Если требуется восстановить данные из архива, остановите службу, сохраните отдельную копию текущего `/var/lib/sigame`, восстановите весь каталог из согласованного архива и проверьте владельца `sigame:sigame` перед запуском. Восстановление старых данных отменяет изменения игр после создания копии.
