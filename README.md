# SIGame — браузерная «Своя игра»

Ведущий создаёт комнату и открывает вопросы; игроки подключаются со смартфонов по QR и нажимают кнопку ответа. Отдельное табло предназначено для проектора. Есть редактор пакетов, изображения/аудио/видео/YouTube, кот, аукцион, финал, зрители, undo, звуки и реакции.

## Локальный запуск

Нужен Node.js 20 или 22 с npm. Для нового Linux-сервера используйте Node.js 22; `better-sqlite3` содержит нативный модуль, поэтому переносить `node_modules` между ОС или версиями Node нельзя.

```powershell
npm ci
npm start
```

Откройте `http://localhost:3000`. Для телефона используйте IP компьютера в локальной сети, разрешите входящий TCP-порт в брандмауэре. QR автоматически подставляет LAN-IP вместо localhost. Другой порт в PowerShell:

```powershell
$env:PORT=3001
npm start
```

На Linux: `PORT=3001 npm start`. Если установка нативного модуля требует компиляции, установите Python 3, make и C++ toolchain (на Debian/Ubuntu — пакеты `python3 build-essential`).

## Как играть

1. В разделе «Пакеты» создайте или импортируйте пакет. Раунды содержат темы и вопросы; у вопроса должны быть положительная цена, правильный ответ и текст либо медиа. Финальный вопрос необязателен.
2. Загрузите медиа в редакторе, сохраните пакет. Экспорт — один файл `*.sigame.json` формата `sigame-pack@1`, локальные загруженные медиа включаются в base64. Внешние ссылки остаются ссылками, встроенные демонстрационные ассеты входят в приложение.
3. На главной выберите пакет и создайте комнату. Покажите QR участникам. Откройте табло по ссылке ведущего (`/room/КОД/screen`).
4. Участники вводят уникальные ники и при желании аватары. Настройте время и режимы в лобби, затем начните игру.
5. Выберите вопрос, прочитайте его, нажмите «Разрешить ответы». Первый нажавший отвечает; ведущий выносит вердикт. Ошибка списывает цену, остальные могут нажать снова.
6. Кота назначает ведущий; аукцион принимает скрытые ставки. В финале игроки с положительным счётом делают ставки и пишут ответ за 30 секунд; ведущий проверяет ответы и завершает игру.

Токены ведущего и игрока хранятся в localStorage браузера. Не очищайте данные сайта во время игры. Удалённый из комнаты игрок не восстанавливается старым токеном.

## Состояние и восстановление

- Снимки всех комнат сохраняются каждые 10 секунд и с задержкой до 250 мс после изменений. SIGINT/SIGTERM выполняют финальную запись перед выходом.
- В снимок входят пакет комнаты, очки, история undo, фаза, ставки аукциона, ставки/ответы/вердикты финала, пауза и оставшееся время.
- При перезапуске клиенты повторяют `session:resume` со своими токенами. Обновление страницы восстанавливает интерфейс из полного состояния.
- Время простоя сервера не вычитается из таймера: отсчёт продолжается с сохранённого остатка. Для отвечавшего действует 10 секунд на переподключение; если он не вернулся, обычный вопрос снова доступен остальным без списания очков. У кота/аукциона без назначенного отвечающего вопрос переходит к показу ответа. При обычном отключении действует то же правило. Пауза замораживает игровые таймеры.
- Старые снимки до версии 2 мигрируют к безопасной фазе; в старом финале ранее не сохранявшиеся ставки восстановить невозможно.
- При аварийном завершении без сигнала возможна потеря изменений после последней успешной записи (обычно до 250 мс). Нельзя гарантировать сохранность при отказе диска.
- Комнаты без подключённых сокетов удаляются после двух часов без активности. Истёкшая комната перестаёт принимать старые токены.
- Медиа и аватары удаляются, когда не используются ни библиотечными пакетами, ни сохранёнными комнатами/undo, и старше 24 часов. Свежая загрузка не удаляется сразу. Обход выполняется раз в минуту.

## Переменные окружения

Файл `.env` автоматически не читается; задайте переменные в оболочке или EnvironmentFile systemd.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | HTTP-порт |
| `HOST` | `0.0.0.0` | Адрес привязки; для nginx — `127.0.0.1` |
| `PUBLIC_URL` | не задан | Внешний URL для QR, например `https://game.example.com` |
| `DATA_DIR` | `./data` от корня проекта | SQLite, uploads и avatars |
| `SNAPSHOT_INTERVAL_MS` | `10000` | Период полной записи снимков, мс |
| `CLEANUP_INTERVAL_MS` | `60000` | Период очистки, мс |
| `ROOM_IDLE_MS` | `7200000` | Срок неактивности пустой комнаты, мс |
| `MEDIA_GRACE_MS` | `86400000` | Минимальный возраст неиспользуемого файла, мс |

Положительные интервалы задаются в миллисекундах. Период пакетной записи после изменения (250 мс) и срок ожидания отключившегося отвечающего (10 секунд) не меняются через окружение.

## Linux: systemd и nginx

Приложение рассчитано на **один процесс Node**. Не запускайте несколько workers/реплик с одной SQLite: оперативное состояние комнат между процессами не синхронизируется.

1. Создайте системного пользователя `sigame` и разместите код в `/opt/sigame`. Установите зависимости на Linux: `npm ci --omit=dev`. Если Node установлен не в `/usr/bin/node`, исправьте `ExecStart` в юните.
2. Скопируйте `deploy/sigame.service` в `/etc/systemd/system/sigame.service`, `deploy/sigame.env.example` в `/etc/sigame.env`, замените домен. `StateDirectory` создаст `/var/lib/sigame` с правами сервисного пользователя. Для переноса существующих игр предварительно остановите старый сервер и перенесите весь `data/`, включая SQLite и медиа, в этот каталог; назначьте владельца `sigame`.
3. Выполните:

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now sigame
sudo systemctl status sigame
curl http://127.0.0.1:3000/healthz
```

4. Установите nginx, certbot с nginx-плагином и утилиту htpasswd (Debian/Ubuntu: `nginx certbot python3-certbot-nginx apache2-utils`). Создайте пароль для редактора/ведущего:

```sh
sudo htpasswd -c /etc/nginx/sigame.htpasswd host
sudo chown root:www-data /etc/nginx/sigame.htpasswd
sudo chmod 640 /etc/nginx/sigame.htpasswd
```

В других дистрибутивах замените `www-data` на группу nginx. Ключ `-c` нужен только при первом создании файла: повторный вызов с ним перезапишет список пользователей.

5. Скопируйте `deploy/nginx.conf` в `/etc/nginx/conf.d/sigame.conf`, замените `game.example.com` на свой домен. Файл подключается внутри секции `http`; не помещайте его внутрь другого `server`. Проверьте конфигурацию и включите HTTPS:

```sh
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d game.example.com --redirect
sudo certbot renew --dry-run
```

Домен должен указывать на сервер, порты 80/443 должны быть доступны. Не передавайте пароль Basic Auth по публичному HTTP до включения HTTPS. Certbot добавляет сертификат, TLS-listener и перенаправление. Убедитесь, что конфиг приложения содержит `PUBLIC_URL=https://ваш-домен`, затем перезапустите `sigame`.

Конфигурация передаёт `Upgrade` и `Connection`, использует HTTP/1.1 и таймаут 75 секунд — больше интервала heartbeat Socket.IO. Справочники: [nginx WebSocket proxying](https://nginx.org/en/docs/http/websocket.html), [Socket.IO behind reverse proxy](https://socket.io/docs/v4/reverse-proxy/).

6. Закройте внешний доступ к 3000; backend привязан к loopback. Страницы ведущего, редактор, содержимое пакетов и загрузка файлов защищены nginx Basic Auth. Игрокам, табло и списку названий пакетов пароль не нужен. При открытии главной страницы публичный список содержит только названия/статистику; содержимое пакетов требует авторизации.

Это игра для доверенного ведущего и гостей, а не сервис с изолированными аккаунтами. Создание комнат через Socket.IO доступно гостям с ограничением частоты. На прямом локальном порту API пакетов доступен без Basic Auth — его защищает nginx. Токен комнаты даёт её ведущему доступ к ответам, поэтому не делитесь hostToken/профилем браузера.

## Безопасность и лимиты

Ники ограничены разрешёнными символами, длина текстов/сообщений ограничена. Пользовательские тексты отображаются как текстовые узлы, не HTML: теги не выполняются. Ссылки медиа принимают только HTTP(S) или известные локальные каталоги; javascript/data URL из пакета запрещены. Импорт проверяет имена файлов, хэши, сигнатуры и размеры. Включены CSP и nosniff.

Socket.IO принимает не более 5 МБ на транспортное сообщение (аватары идут в base64); обычный запрос ограничен 16 КБ, вход с аватаром — 3 МБ. Не более 20 buzz:press за секунду на идентификатор игрока, 600 событий за 10 секунд на сокет, 30 созданий комнат за минуту с адреса. HTTP API — до 600 запросов в минуту с IP. Ограничения в памяти предназначены для одного процесса; перед публичным сервисом нужны дополнительные инфраструктурные лимиты.

Загрузки: изображения до 5 МБ, аудио до 10 МБ, видео до 100 МБ; импорт JSON до 150 МБ. Большой набор медиа может превысить общий предел из-за base64. Проверка формата по сигнатуре не заменяет перекодирование недоверенных медиа.

## Резервные копии и обновления

Для согласованной резервной копии остановите `sigame`, скопируйте весь `DATA_DIR` в защищённое место, затем запустите сервис. Не копируйте только `sigame.db` у работающей SQLite в WAL-режиме: свежие данные могут находиться в `-wal`. Храните токены из БД как секреты.

При обновлении остановите сервис, сохраните резервную копию, обновите код, выполните `npm ci --omit=dev`, запустите сервис и проверьте `/healthz` и переподключение. Не удаляйте рабочую папку данных для тестов.

## Автотесты

Для тестирования нужны devDependencies: `npm ci`. Синтаксис можно проверять `node --check путь/файл.js`.

```sh
node test/stability.mjs
```

Этот тест самостоятельно создаёт отдельные временные БД, запускает дочерний сервер на свободном порту, проверяет отключение на 10 секунд, перезапуски игры/аукциона/финала, очистку, ограничения и восстановление итогов. Временные данные оставляются для диагностики; путь печатается в конце. Для фактической проверки конфигурации reverse proxy задайте `NGINX_BIN` (полный путь к nginx), при необходимости `TEST_TMPDIR`; выполняются `nginx -t`, HTTP-auth и WebSocket upgrade через настоящий nginx.

Существующие сценарии требуют **отдельной тестовой копии** проекта с собственной БД и сервером на 3000. Выполняйте последовательно:

```sh
node test/e2e.mjs
node test/late-judge.mjs
node test/game.mjs
node test/host.mjs
node test/media.mjs
node test/packs.mjs
node test/special.mjs
node test/final-resume.mjs
```

`npm run test:e2e` запускает только первый сценарий, не всю регрессию. `test/restart.mjs setup` и `verify` — старый ручной двухшаговый тест; основной автоматический сценарий перезапуска теперь в stability.mjs.

## Типичные проблемы

- **EADDRINUSE**: сервер на этом порту уже работает. Остановите только свой предыдущий процесс через Ctrl+C или `systemctl stop sigame`; либо выберите другой порт. Не завершайте все node.exe.
- **Телефон не подключается**: общий Wi-Fi, корректный LAN-IP/домен, firewall, PUBLIC_URL. localhost на телефоне — сам телефон.
- **Отключения каждые ~60 секунд / 400 при upgrade**: проверьте WebSocket-заголовки и таймауты nginx, используйте готовый конфиг.
- **401 на редакторе/загрузке**: войдите с учётной записью nginx Basic Auth; игрокам пароль не требуется.
- **Нет звука**: разблокируйте звук нажатием, проверьте mute; браузер может блокировать autoplay, YouTube на табло стартует без звука.
- **413**: превышен лимит файла/импорта в nginx или приложении.
- **Нет старых комнат**: проверьте DATA_DIR, права пользователя systemd и журнал `journalctl -u sigame -n 100`. Не создавайте новую пустую БД вместо существующей.
- **Ошибка better-sqlite3 после переноса**: выполните npm ci на целевой ОС/версии Node, не переносите node_modules.

## Финальный чек-лист ручной проверки

- [ ] Открыть ведущего, двух игроков на телефонах и табло; проверить QR, аватары, кик, смену ника и зрителя.
- [ ] Создать пакет с текстом, картинкой, аудио, видео, котом, аукционом и финалом. Сохранить, экспортировать, импортировать и проверить медиа/финал.
- [ ] Проверить скрытие/показ вопроса игрокам, порядок открытия кнопки, гонку двух нажатий, верный и неверный ответы.
- [ ] Проверить паузу, undo, ручной счёт, пропуск, передачу выбора, фальстарт и досрочное завершение.
- [ ] Отключить отвечающего: через 10 секунд остальным снова доступна кнопка. При возврате раньше срока ответ продолжается.
- [ ] Перезапустить сервис посреди ответа, аукциона и финала; обновить все страницы. Сохранены очки, право ответа, ставки, текст финального ответа и вердикт.
- [ ] В финале после обновления ведущего доступны нужные кнопки; «Завершить раунд» скрыто; завершение игры показывает одинаковые итоги на всех экранах.
- [ ] Через HTTPS проверить реальные смартфоны, звук, загрузку/проигрывание медиа, реакции и mute; Socket.IO перешёл в WebSocket.
- [ ] Проверить /healthz, ограничения, 401 редактора без пароля и восстановление после `systemctl restart sigame`.
- [ ] Убедиться, что резервная копия DATA_DIR сделана, 3000 не открыт наружу, TLS продлевается, активные комнаты и используемые медиа не удаляются очисткой.
